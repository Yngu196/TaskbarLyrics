## 3. 文档规划 vs 实际实现 — 关键差异

| #  | 文档规划                   | 实际实现                   | 原因                          |
| -- | ---------------------- | ---------------------- | --------------------------- |
| 1  | SetParent 嵌入子窗口        | 独立浮动窗口覆盖               | Win11 任务栏结构变化，SetParent 不稳定 |
| 2  | C++20                  | C++17                  | 功能无影响                       |
| 3  | SetDrawingEffect 着色    | PushAxisAlignedClip 裁剪 | 更简单可靠的实现                    |
| 4  | 绑定模式+进程监控              | Native Host 托管（v0.4.0） | 更优的生命周期管理                   |
| 5  | WS\_EX\_TRANSPARENT 穿透 | 不使用穿透                  | 需接收鼠标事件支持交互                 |
| 6  | 日志写入 %TEMP%            | exe 同级 debug.log       | 可移植路径                       |
| 7  | 手动编辑 JSON              | D2D 原生 GUI             | 完整配置界面                      |
| 8  | 无拖动功能                  | 支持拖动定位                 | 新增需求                        |
| 9  | 无 Z-order 保持           | 三重 TOPMOST 防护          | 修复点击被覆盖问题                   |
| 10 | TerminateThread 强杀     | 协作式 join() 退出          | 代码审查安全隐患修复                  |
| 11 | 散落魔数                   | constants.h 集中管理       | 代码审查建议                      |
| 12 | 无异常恢复                  | WM\_TIMER catch 重试     | 防止渲染器卡死                     |
| 13 | 无配置校验                  | std::clamp 范围验证        | 防止非法值                       |
| 14 | 无长歌词滚动                 | 跑马灯 6 状态机              | 设计需求                        |
| 15 | 无 API 自动开启             | api\_enabler 模块        | 用户需求                        |
| 16 | 无频谱显示功能               | WASAPI 频谱捕获 + 频谱条渲染    | 纯音乐场景增强（v1.0.5）            |
| 17 | 鉴权 Token 硬编码常量         | 注册表 UUID 动态读取           | 安全性提升                      |
| 18 | 单一日志文件                 | 5 级日志 + 5MB 自动轮转        | 日志可维护性提升                  |

### 6.1 窗口宽度异常（Issue #20）根因分析

**现象：** 用户反馈歌词窗口宽度被压缩到约 100px，只显示歌曲封面和几个字，无法正常显示歌词。

**根因**（2026-08-10 由用户调试日志确认）：

1. 该用户环境：Windows 10 22H2 (19045)，2560×1440，100% DPI。
2. UIA 检测到 `MSTaskListWClass` 边界矩形为 `(96,1400,2256,1440)`，`TrayNotifyWnd` 为 `(2256,1400,2560,1440)` —— **任务列表右边缘与托盘左边缘完全相等（2256 == 2256）**；任务栏布局变化后两者依然同步右移（2280 == 2280）。
3. 真实任务栏中任务列表永远不会贴到托盘（中间存在折叠箭头/留白），说明该机器上 UIA 将任务列表边界矩形多报到了托盘边缘（视觉上任务列表实际提前约 100–200px 结束），属于 Win10 22H2 的 UIA 边界矩形异常。
4. 旧逻辑计算 `availableWidth = trayRect.left - taskListRect.right = 2256 - 2256 = 0`，被 `MIN_LYRIC_AVAILABLE_WIDTH = 100` 下限钳制 → 窗口只剩 100px，封面占满窗口、歌词被裁成几个字。

**修复方案：**

1. **几何合理性校验**（shell_companion.cpp）：任务列表右边缘 ≥ 托盘左边缘 − 2px 时判定"任务列表与托盘重叠"（物理上不可能）→ 忽略任务列表矩形，回退为使用整段任务栏宽度计算 `availableWidth` → 窗口恢复 360px 默认宽度。
2. **手动窗口宽度设置**：设置 → 窗口 → 窗口宽度（0=自动，100–600 dp），作为最小宽度兜底，供任务栏确实拥挤的场景使用；保存后热更新即时生效。
3. **增强定位调试日志**：`[SHELL-COMPANION] Pos:` 现在打印 taskList/tray/rebar 完整矩形、found 标志、rightEdge、availableWidth、widthOverride，便于远程定位。

**验证：** 新版本日志显示 `taskListRect invalid ... overlapTray=1, ignore` → `foundTL=0` → `availableWidth=2256` → `w=360`（即使 `widthOverride=0` 也正常）。用户反馈"新版本触发不了这个问题，将手动调节的长度调为 0 也无法触发"，确认修复生效。
